# 技能开发

技能是一段**可被条件触发**的指令文本。它不执行代码，只影响模型的行为方式——所以在正确的时机注入正确的几句话，比塞一大堆工具更能省钱、也更稳。

## 文件结构

一个技能就是一个目录，里面至少有一个 `SKILL.md`：

```
my-skill/
  SKILL.md          # 必需
  references/       # 可选：给模型按需读取的补充材料
```

`SKILL.md` 由 frontmatter 和正文组成：

```markdown
---
name: token-saver
description: 用最少的 token 把事做完
when: 省token, token, 精简, 太长, 冗长, 简短
---

# 输出纪律

1. 不复述需求，不写"好的，我来…"。
2. 改代码只给 diff 或改动块，不重贴整文件。
3. 一次说清，不要分多轮试探。
```

| 字段 | 说明 |
| --- | --- |
| `name` | 显示名，也用于去重 |
| `description` | 一句话说明，出现在技能面板 |
| `when` | 逗号分隔的关键词，**命中用户输入就注入** |
| 正文 | 原样拼进系统提示词（在 `# 当前激活的 Skill 指引` 段落里） |

关键词匹配是大小写不敏感的子串匹配。中文没有分词，因此 `when` 里尽量写2–4字的短词，命中率更高。

## 内置技能

5 个，源码在 `src-tauri/src/skills/builtin/`，通过 `include_str!` 编进二进制，因此永远可用、不可删除（可以停用）。

| 技能 | 触发场景 | 作用 |
| --- | --- | --- |
| `token-saver` | "省 token"、"太长"、"精简" | 输出纪律：不复述、只给 diff、不分多轮 |
| `diff-surgeon` | "改一下"、"重构"、"替换" | 先读后改、最小编辑、禁止整体重写 |
| `repo-scout` | "这个项目"、"结构"、"入口" | 先摸清目录与入口再动手，避免瞎猜路径 |
| `commit-craft` | "提交"、"commit"、"写信息" | 提交信息规范：一句话主旨 + 要点列表 |
| `code-reviewer` | "review"、"检查"、"有没有问题" | 按 正确性 → 边界 → 性能 → 风格 顺序给结论 |

## 安装

三种来源，都在 `技能` 面板的输入框里粘贴即可：

| 来源 | 示例 |
| --- | --- |
| 本地目录（含 `SKILL.md`） | `D:\skills\my-skill` |
| 单文件 URL | `https://example.com/SKILL.md` |
| Git 仓库 | `https://github.com/user/skill-repo` |

安装后落在 `~/.irixen-code/skills/<id>/`，重启后仍在。

## 开关与自动匹配

- 面板上的开关控制**是否参与匹配**（停用后即使命中关键词也不注入）
- 设置 → Agent → "按关键词自动加载技能" 是总开关
- 引擎每次发送前都会重新计算匹配，因此开关即时生效

## 写技能的经验

**该写**

- 输出格式约束（"只给 diff"、"结论先行"、"不超过 5 行"）
- 领域约定（"这个项目的迁移文件在 `db/migrations`"）
- 明确的禁止项（"不要新增依赖"）

**不该写**

- 大段背景资料 → 放到 `references/`，让模型自己读
- 通用编程常识 → 模型本来就会，写了只是浪费 token
- 与 `system_prompt` 重复的内容

**关键词要克制**
`when: 代码` 会让技能在几乎所有请求里触发，等于把成本乘上每次对话。宁可窄一点。

## 调试

```bash
# 看当前加载了哪些技能
cat ~/.irixen-code/skills/*/SKILL.md

# 改完内置技能后重建
npm run app:build
```

对话里出现 `已加载 skill: xxx` 的状态提示，就说明注入生效了。
